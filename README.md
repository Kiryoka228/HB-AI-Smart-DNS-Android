# HB AI Smart DNS Android 1.24 — APK Web Fork

**Исходный код Android-приложения без Termux.** JavaScript/HTML/CSS остаются интерфейсом, Java — минимальный системный слой для тех действий, которые WebView не может выполнять сам: VpnService, root/su, UDP/TCP DNS и TLS-диагностика.

**Статус:** исходный Gradle-проект, а **не готовый APK**. В среде создания проекта нет Android SDK/Gradle и нельзя скачать их зависимости. `tests/run-offline.sh` выполняет 16 offline-тестов на Java 17; это **не тест установки на телефон**, не сертификат успешной сборки и не проверка root/VPN на реальном Android. После сборки APK необходимо проверить на устройстве. Собирать APK без Android SDK на самом телефоне можно, так как SDK нужен только на этапе сборки (например, в GitHub Actions).

## Как собрать APK, не устанавливая Android SDK

1. Создайте приватный GitHub-репозиторий и поместите туда **содержимое этой папки** (включая скрытую `.github/workflows/android-apk.yml`).
2. Откройте вкладку **Actions → Build installable Android APK → Run workflow**.
3. После успешной сборки откройте завершившийся запуск → **Artifacts** → `HB_AI_Smart_DNS_Android_1.24.1-debug-APK`.
4. Извлеките `app-debug.apk` и установите на Android 8.0+ (если система разрешает установку APK из выбранного источника). Установочная сборка подписывается стандартным **временным debug-ключом** CI: при повторной сборке ключ может измениться, поэтому для стабильных обновлений требуется постоянная release-подпись.

Если уже имеется компьютер с Android SDK 35 и Gradle 8.11.1+, используйте `bash build-apk.sh`. Исходный проект не использует сторонние библиотечные зависимости в самом приложении (Android Gradle Plugin нужен лишь при сборке).

## Как работает на Android

- Веб-интерфейс **упакован внутри APK** и работает через WebView с локальными ресурсами; сайт и локальный Node.js-сервер не нужны.
- При открытии проверяется `su`. Если менеджер Magisk/KernelSU и root установлены, Android может предложить разрешить root. При нажатии «Включить» (и успешном разрешении root) включается локальный UDP/TCP DNS-прокси на 53535 и отдельные цепочки iptables, с попыткой перенаправить и IPv6 DNS.
- Без root предлагается системное разрешение **VpnService**. В его локальный интерфейс маршрутизируются только виртуальные DNS-адреса `10.111.0.1/32` и `fd66::1/128`; остальной трафик не идёт в TUN. Приложение отправляет DNS-запросы напрямую к выбранным серверам и отдаёт DNS-ответы системе. Собственные DNS-сокеты защищаются через `protect`, чтобы не образовывать петлю.
- Если root доступен, но `iptables` не работает, программа откатывает root-правила и запрашивает разрешение на VPN.
- VPN/root-сервис работает в foreground с постоянным уведомлением и кнопкой отключения.
- Сохранены четыре исходных провайдера, их адреса и шесть диагностических сайтов, кнопки «Проверить» и «Найти лучший», выбор провайдера, открытие сетевых настроек, оригинальная визуальная основа и лицензия.

## Что ОС всё равно ограничивает

**VPN — не root.** Без root нельзя отключить Private DNS в режиме строгого DNS-over-TLS, изменять чужие системные настройки, заставлять приложения с собственным DoH использовать наши DNS или одновременно иметь два обычных VPN без поддержки ОС. Нельзя считать, что все сайты и приложения обязательно используют Smart DNS.

DNS-VPN обрабатывает IPv4/IPv6 UDP-пакеты к двум виртуальным DNS-адресам. **DNS через TCP в VPN-режиме пока не реализован** (в root-режиме TCP-порт 53 поддерживается), а DNS-ответы, превышающие MTU, заменяются на SERVFAIL. Это техническое ограничение текущего кода, и до реального тестирования на устройстве сборку нельзя называть полностью эквивалентной настольной версии. Диагностический TLS намеренно проверяет доступность без проверки сертификата (как в исходном проекте): результат не должен использоваться как подтверждение безопасности соединения.

Root зависит от `su`, `iptables`/`ip6tables`, SELinux/netd и прошивки. Возврат Private DNS и очистка наших цепочек предусмотрены при остановке, плюс root-watchdog для аварийной остановки. **Восстановление на всех прошивках не гарантировано**. Если после сбоя DNS перестаёт работать, откройте настройки сети и выключите VPN; на root-устройстве удалите только цепочки `HB_AI_DNS4`, `HB_AI_DNS6` (см. `RECOVERY.md`).

## Требования и безопасность

- Android 8.0+ (`minSdk 26`), target/compile SDK 35.
- Не требуется Termux, Node.js, Android SDK или Java на **телефоне**.
- Запрашиваются `INTERNET`, сетевое состояние, foreground-service и системное одобрение VPN. Root запрашивается отдельно через установленный root-менеджер, если он присутствует.
- Внешние ссылки открываются в системном браузере, а привилегированный JS-мост принимает только фиксированные команды и остаётся недоступным загружаемым извне страницам.
- Исходный desktop-проект: HB AI Smart DNS 1.23, лицензия MIT, включена в архив.


## 1.24.1 Android compatibility

Foreground Service type is now `specialUse` in both the manifest and Java service, avoiding the system-only `systemExempted` type on stock Android. VPN startup posts a foreground notification before TUN establishment. VPN revocation triggers full root-rule cleanup if ever applicable. This is a technical source revision; runtime behavior on physical devices has not yet been verified.
